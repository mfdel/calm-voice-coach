# ParentPilot: Product Documentation

## 1. Product Requirement Document (PRD)

### 1.1 Executive Summary
**ParentPilot** is an AI assistant designed to provide instant, non-judgmental, and style-aligned guidance to parents during high-stress situations. In the revised v1, the experience is manually triggered: the parent taps for help, provides a quick description of the problem, and receives grounded advice generated by an LLM using structured family context and retrieved parenting strategies.

### 1.2 Target Audience
* **Primary:** Parents of toddlers and school-aged children (ages 1-10) navigating behavioral challenges.
* **Secondary:** Nannies, grandparents, and caregivers requiring consistency with the parents’ methods.

### 1.3 Revised Product Roadmap: v1 (MVP v2) vs. Long-Term Plan

| Feature Category | **v1: Guided SOS with RAG + LLM** | **Long-Term Plan / Ideas** |
| :--- | :--- | :--- |
| **Activation** | Manual SOS trigger via home screen button or lock-screen widget | Passive listening / predictive detection |
| **Input** | Parent-selected problem, typed summary, or short voice note | Video/photo analysis, ambient listening |
| **Output** | **Big Text** coaching, short scripts, calming haptics | Whisper mode, earbud coaching, smartwatch flows |
| **Intelligence** | Cloud LLM with structured prompting | On-device reasoning / local LLM |
| **Knowledge Layer** | Curated parenting scenarios + suggestions retrieved with RAG | Expanded predictive models and advanced personalization |
| **Collaboration** | Single-user history and profile in initial scope | Village Sync and multi-caregiver coordination |

### 1.4 Updated Value Proposition

**ParentPilot is not just a fast LLM wrapper.** It combines a curated database of common parenting situations, retrieval-augmented generation (RAG), child-specific context, parenting preferences, red lines, and past incident history to produce advice that is both fast and meaningfully grounded in how a specific family wants to parent.

### 1.5 Functional Requirements

#### 4.1. The "SOS Mode" (Core Engine)
* **Trigger:** Immediate activation via a large button on the home screen or a lock-screen widget.
* **Input:** The parent chooses a common problem (e.g., not eating, throwing food, refusing to get dressed) and can optionally add a typed note or short voice note.
* **Prompt Assembly:** The system builds an intelligent prompt using:
	* Child information
	* Parenting preferences and "Red Lines"
	* Past incidents and prior feedback
	* Retrieved relevant examples and strategies from the curated parenting database
* **Output:** Generates 2-3 short, actionable suggestions and one example script in large, readable text.
* **Accessibility:** Must feature **One-Handed Ergonomics** (all buttons in the bottom third) and **High-Contrast Mode** (massive bold text for easy reading during stress).

#### 4.2. Quality Control: The "Red Lines" Engine
* **Input:** During setup, parents select specific methods/actions they **never** want the app to suggest (e.g., "No cry-it-out," "No time-outs," "No physical discipline").
* **Enforcement:** The AI filtering layer must scan every generated suggestion against the "Red Lines" database before displaying it to the user.

#### 4.3. Parenting Knowledge Base + RAG
* **Curated Database:** The system maintains a structured database of common parenting problems (e.g., refusing meals, bedtime resistance, sibling conflict, transitions, dressing, cleanup resistance).
* **Grounded Retrieval:** Before generating advice, the app retrieves relevant strategies, scripts, and prior similar incidents.
* **Goal:** Improve relevance, consistency, and speed so the product is more valuable than a generic chatbot interaction.

#### 4.4. Profile & Context
* **Child Profile:** Stores age, developmental stage, and known triggers (e.g., "hates loud noises," "sensitive to transitions").
* **Parenting Preferences:** Stores household values, preferred coaching style, and excluded methods.
* **Incident History:** Stores past SOS sessions, suggestions shown, and parent feedback on whether the advice worked.

#### 4.5. Retrospective Analysis: "The Nightly Debrief"
* **Function:** A low-pressure evening summary of the day's SOS incidents.
* **Feedback Loop:** Parents can "Reject & Recalibrate." If a suggestion felt wrong, the parent flags it, and that feedback becomes part of the context used for future prompting and retrieval.

### 1.6 Non-Functional Requirements

#### 5.1. Privacy & Data Security (The "Trust Fortress")
* **No Passive Listening in v1:** The app does not listen in the background. All input is explicitly user-triggered.
* **Cloud LLM with Minimal Context:** v1 uses a cloud LLM, but only the minimum required context should be sent.
* **Data Minimization:** No raw audio is saved long term. Voice input, if used, is transcribed and discarded after processing.
* **Encryption:** All stored child profiles and incident history must be encrypted at rest and in transit.

#### 5.2. Haptic Feedback
* The app should use a rhythmic haptic "pulse" (vibration) during SOS mode to help the parent pace their breathing and stay regulated.

### 1.7 Success Metrics (KPIs)
* **Incident Resolution Rate:** User-reported success after an SOS session.
* **Alignment Score:** % of AI suggestions accepted/liked by the parent during the Nightly Debrief.
* **Time-to-Advice:** Speed from app trigger to first actionable text (Target: < 5 seconds on a normal connection).
* **Grounding Quality:** % of sessions where retrieved examples are rated relevant by the parent.

## 3. Long-Term Plan / Ideas

These ideas are intentionally **out of scope for v1**, but should be preserved for future exploration.

### 3.1 Deferred Intelligence Ideas
* **Passive Listening:** Ambient audio analysis to detect escalation without explicit parent input.
* **On-Device Reasoning / Local LLM:** Run more of the decision engine locally for privacy, offline mode, and speed.
* **Predictive AI:** Detect likely meltdowns before they happen based on time, triggers, and prior incidents.

### 3.2 Deferred Input / Output Ideas
* **Video/Photo Situational Analysis:** Use camera input to understand context beyond the parent description.
* **Whisper Mode:** Audio coaching delivered through earbuds.
* **Shake to Start / Smartwatch App:** Faster access beyond the phone UI.

### 3.3 Deferred Collaboration Ideas
* **Village Sync:** Shared child profile, parenting preferences, and incident history across parents, nannies, and caregivers.
* **Cross-Caregiver Alignment:** Shared learning about what works best for a specific child across the household.

### 3.4 Deferred Knowledge & Analytics Ideas
* **Expanded Parenting Database:** A larger expert-reviewed library of common scenarios, scripts, and interventions.
* **Behavioral Trend Analysis:** Weekly or monthly reporting on triggers, successful scripts, and caregiver patterns.
* **Smarter Feedback Loops:** More advanced ranking and personalization of suggestions based on outcomes over time.
